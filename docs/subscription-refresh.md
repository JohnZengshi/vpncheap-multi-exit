# 订阅刷新与安全更新

## 使用

- 启动 Broker 后后台自动联网更新，默认成功间隔 300 秒，可用
  `-CatalogRefreshSec` 调整，实际拉取间隔限制为 60 至 86400 秒。关闭控制台页面不会停止后台更新。
- 控制台的“更新订阅”按钮立即拉取，显示更新时间、节点数量和失败状态。
  手动请求有 10 秒冷却，文件锁确保自动和手动任务不会同时抓取。
- 独立命令：`pwsh -NoProfile -File scripts/subscription-refresh.ps1 -Force`。
  不带 `-Force` 时遵守上次记录的下次更新时间。
- 失败按 60、120、240、480、900 秒退避。空目录、无效节点、升级提示伪节点，
  或原目录不少于 10 项却突然减少到一半以下，均拒绝覆盖旧目录。
- 登录过期时在 VPNCheap 客户端重新登录，再点击更新。不会自动保存新账号或改写凭据。

## 出口更新规则

逻辑出口槽位继续使用旧 `nodeHash`，`port-leases.json` 和 9Router 绑定保持不变。
当前配置独立加密保存在 `runtime/nodes/<slot>.dpapi.json`，启动时优先使用它，
不依赖供应商是否保留旧 ID。新目录按相同协议、相同国家筛选，再依次尝试：

1. 唯一供应商 ID。
2. 唯一旧地址和端口。
3. 忽略大小写、空白及编号前导零后的唯一精确名称。

匹配不唯一或节点消失时保留旧配置，标记待核对，不自动选择同地区其他线路，
不自动切换协议。匹配成功且配置变化时：

1. 在临时回环端口启动候选服务并进行真实代理健康检查，旧服务继续运行。
2. 获取全局更新锁，一次仅更新一个出口。
3. 验证通过后关闭临时服务，在原固定端口切换配置并再次检查健康。
4. 成功后保存新配置；固定端口启动、健康检查或快照写入失败时恢复旧配置。

更新锁覆盖整个验证和切换过程。切换会中断该出口已有连接，并非零停机更新。
回退启动失败时 Worker 继续尝试旧配置并报告失败，不换端口。
同一失败配置默认 300 秒后才再次验证；其他出口不会因为一次订阅刷新被停掉。

## 旧出口迁移

本次部署不会主动重启正在运行的九个 Worker。PowerShell 进程中已加载的函数
不会因为文件修改而更新，完整的新调度与安全切换逻辑在后续维护重启后生效。
拉取脚本自身也检查更新时间，避免旧 Broker 因时区解析问题过度请求网络。

没有旧配置快照、且供应商 ID 已经消失的槽位无法可靠自动恢复。
确认旧线路对应的新节点后，可在不更改选择列表和租约的前提下提交映射：

```powershell
pwsh -NoProfile -File scripts/exit-map.ps1 -SlotHash <旧出口哈希> -SourceHash <新节点哈希>
```

两个哈希可从控制台状态及“配置出口”列表获得。命令只接受相同协议和国家，
记录到 `runtime/exit-config.json` 的 `replacements`，不直接启动或停止服务。
新版 Worker 验证新线路通过后才启用。旧 Worker 仍需维护重启。

## 安全与依赖

- 复用本机已安装的 `VpncheapWindows.Core.dll` 的订阅服务及客户端真实版本标识，
  未硬编码订阅 URL，也未伪造客户端版本。升级安装可能改变 API，需要重新兼容。
- 临时副本承接服务内部的状态写入，凭据适配器只允许读取；原始
  `%APPDATA%\vpncheap\app_state.json` 不回写。
- 订阅目录和出口快照使用当前用户 DPAPI，附加熵绑定文件绝对路径。
  移动目录、换机器或换用户后不可直接解密；不要删除旧快照来处理订阅故障。
- 对外状态只包含结果和错误哈希，不返回订阅链接、节点密码或解密后的配置。
- 手动更新接口为同源 `POST /api/subscription/refresh`，要求
  `X-Exit-Control: 1`，沿用控制台的本机控制请求校验。
