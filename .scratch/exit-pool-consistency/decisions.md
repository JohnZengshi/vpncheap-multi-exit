# 出口与代理池一致性：已确认决策

状态：grill-with-docs 访谈决策已记录；正式规格已发布为同目录的 `spec.md`，标记为 `ready-for-agent`；尚未拆分实施任务。

## 目标

让用户明确看到配置节点、实际节点、本地入口、9Router 代理池与 Provider 连接之间的关系。解决候选重复、同名冲突和同步状态不清晰的问题。

## 已确认范围

- 本次实现基础流程修复；所有 Provider 的固定公网 IP 保护留待后续独立工作。
- 保留自动备用；界面明确区分配置节点与实际节点，并展示备用状态。
- 当前选中的四条线路作为已有配置处理，不自动建立已批准的公网 IP 基准。
- 本次不自动启用 Provider，也不为未绑定连接分配出口。
- 自动维护本工具有明确归属记录的代理池；外部池不自动接管。
- 有绑定且无明确替代关系的历史池保留，不能因同名而迁移绑定。
- 同一节点的重复引用合并；同名不同身份的节点保留并提供区分信息。无法唯一确认的映射明确标记待核对。
- 已有出口与可新增节点分开表达；保留历史恢复信息，但不把历史快照全部当作普通新节点。

## 本轮确认

1. 仍有 Provider 绑定的出口禁止直接取消，列出受影响连接；先迁移或解除绑定，再取消。
2. 取消节点 A、选择节点 B 表示停用 A、启用 B，不自动转移端口或绑定。本次不增加手动“更换节点”操作。
3. 出口生效但代理池同步失败时保留出口，显示部分成功及失败原因，提供手动重试并继续后台重试。

适用边界：停用的 Provider 连接仍可能保留绑定；自动选择和减少数量同样不能绕过取消保护。取消保护只限制新的配置操作，不倒推删除或自动迁移既有历史池。

## 截图问题的预期处理

- 彰化 39033 与原 Claude 绑定的 39030 不能仅凭名称相同视为同一出口。
- 为当前出口建立独立、可追溯的池对应关系；原池在绑定仍存在时标记为历史保留。
- 台北同名候选先按身份及映射核实；展示区分信息，避免仅按名字去重。
- “出口健康”“代理池测试通过”“绑定关系完整”分别表达，不互相替代。

## 后续规格需要覆盖的验证场景

- 同名不同节点、历史快照重复引用、备用占用及订阅更新后的身份保持。
- 有绑定出口在手动取消、减少数量及自动选择下均受保护。
- 同步失败保留出口；重复重试不重复建池，配置变化后不执行旧操作。
- 有绑定历史池保留、外部池保护、明确迁移先测试再回读确认。
- 页面能追踪完整关系，并准确呈现保存、出口调整、同步及失败重试阶段。
