# 出口、订阅节点与 9Router 代理池一致性

Status: ready-for-agent

## Problem Statement

用户不能从当前界面可靠判断一个逻辑出口对应哪个订阅节点、哪个本地入口和哪个 9Router 代理池。候选列表混合订阅节点与历史出口快照，同名条目缺少区分信息；自动备用后，配置节点与实际节点的含义进一步混淆。

会话截图中，彰化逻辑出口使用 39033，同名代理池仍指向 39030 并绑定 Claude。当前出口显示“无代理池、名称冲突”，旧池却显示“测试通过”。台北 01、02 出现同名候选，用户无法判断重复、备用占用或选择数量限制。仅按名称去重或迁移会错误合并不同对象，保留代理池也不能保证已经停止的出口仍可用。

配置保存、出口实际生效与代理池同步是不同阶段，当前体验缺少一致的状态表达。用户需要修复基础管理流程，随后再单独建设所有 Provider 的固定公网 IP 保护。

## Solution

以持续的逻辑出口身份组织管理流程，分别展示配置节点、实际节点、本地入口、对应代理池及绑定连接。通过明确的节点映射消除重复引用，同时保留同名但不同身份的节点；把历史记录和普通可选节点分开表达。

本工具自动维护托管代理池，通过归属记录识别对象，避免名称冲突阻塞新出口建池。对仍有绑定的出口实施取消保护；保留无明确替代关系的历史池。出口已经生效而同步失败时保留运行结果，显示部分成功并重试。

保留现有自动备用行为，明确展示其实际节点。固定公网 IP 检测、锁定和异常阻断均不在本次交付范围。

## User Stories

1. 作为操作者，我希望每个逻辑出口有持续身份，以便订阅名称或实际节点变化后仍能识别原出口。
2. 作为操作者，我希望同时看到配置节点与实际节点，以便理解备用切换后的流量路径。
3. 作为操作者，我希望旧配置无法恢复时显示待核对，以免把备用节点误认为原选择。
4. 作为操作者，我希望每个出口显示本地入口及对应代理池，以便快速确认两者是否一致。
5. 作为操作者，我希望从 Provider 连接追踪到代理池、入口和实际节点，以便定位断开的关系。
6. 作为操作者，我希望同一订阅节点的重复引用合并，以免重复选择同一资源。
7. 作为操作者，我希望同名不同节点显示协议与身份信息，以便选择正确对象。
8. 作为操作者，我希望已有出口与可新增节点分开显示，以免将历史快照当作新线路。
9. 作为操作者，我希望候选数量、筛选数量及已选数量含义明确，以便理解配置容量。
10. 作为操作者，我希望不可选条目显示具体原因，以便区分数量已满、自动选择和节点已被占用。
11. 作为操作者，我希望看到实际节点被哪个出口使用，以免无意创建重复占用。
12. 作为操作者，我希望取消后重选可恢复原出口身份与端口租约，以便维持可追溯性。
13. 作为操作者，我希望存在绑定的出口无法直接取消，以免留下指向失效入口的连接。
14. 作为操作者，我希望取消被拒绝时看到受影响的连接，以便先迁移或解除绑定。
15. 作为操作者，我希望停用连接的绑定仍受保护，以免稍后启用时使用失效入口。
16. 作为操作者，我希望自动选择及减少数量遵守相同保护规则，以免间接绕过限制。
17. 作为操作者，我希望取消 A、选择 B 不自动转移绑定，以免普通勾选改变 Provider 路由。
18. 作为操作者，我希望健康出口可自动建立托管代理池，以便完成基础接入。
19. 作为操作者，我希望不同出口同名时仍能独立建池，以免历史池阻塞当前出口。
20. 作为操作者，我希望工具只维护有明确归属的池，以免影响其他工具配置。
21. 作为操作者，我希望有绑定的历史池保留并说明原因，以便自行安排迁移。
22. 作为操作者，我希望明确迁移经过目标测试及绑定回读确认，以免在失败后删除原池。
23. 作为操作者，我希望多次同步不重复建池，以便安全重试。
24. 作为操作者，我希望区分保存成功、出口调整和代理池同步，以便知道配置是否真正可用。
25. 作为操作者，我希望同步失败保留已生效出口并允许重试，以免为界面一致性重复中断连接。
26. 作为操作者，我希望健康、池测试和绑定完整性分别显示，并带检查时间，以免旧结果掩盖当前异常。
27. 作为操作者，我希望桌面和移动端均可完成选择、核对及重试，以便在不同设备上管理。
28. 作为维护者，我希望旧配置和台账可兼容读取，以便升级不重分配端口或静默改变绑定。
29. 作为维护者，我希望隔离回归覆盖冲突、中断及并发变化，以便错误分支可重复验证。
30. 作为操作者，我希望真实环境完成实际写入验收，以便确认真实 9Router 接口和运行流程可用。

## Implementation Decisions

### 身份与候选

- 遵循已接受的“逻辑出口身份独立于实际节点”及“保护已有绑定，允许出口与代理池分步生效”两项架构决策。
- 沿用现有逻辑出口身份、端口租约和已归属的代理池身份。名称只作为显示信息；实际节点切换不重新分配逻辑出口身份。
- Broker 的候选整理与状态发布、Worker 的节点状态、Dashboard 的快照及选择接口共同表达配置节点与实际节点。无法从旧数据恢复配置节点时保留未知和待核对状态，不猜测原选择。
- 合并相同来源身份或已有明确映射的重复引用。名称相同、地区相同或公网 IP 相同均不足以合并节点；映射歧义显示待核对，不自动认领。
- 选择界面区分已有出口与可新增订阅节点。未选中的历史快照保留作恢复记录，不作为额外的新节点候选重复出现。已选历史出口不可因缺少当前订阅映射而从配置中消失。
- 同一节点重新选择时复用已有明确出口映射与租约；存在多个冲突历史映射时要求核对，不新建猜测关系。已清理的代理池不承诺恢复原池身份。
- 实际节点的占用关系在界面和后端共同校验；已有出口继续使用自己的实际节点不属于重复新增。不得新选一个已被其他出口实际占用的节点。
- 同名不同节点显示协议及稳定短身份；候选统计、筛选与选择校验使用同一份整理后的目录。不可选原因包含自动选择、数量限制、占用或映射待核对。

### 配置与接口

- 保持既有选择请求的兼容性；在快照、候选及状态响应中补充配置节点、实际节点、占用归属、不可选原因、出口与池的对应状态。旧数据缺字段时返回明确的未知状态。
- 普通勾选只表达启用和停用出口，不承载手动换节点或绑定迁移。本次不新增手动“更换节点”操作，也不新增 Provider 绑定管理页面；取消受保护出口时指向已有绑定管理方式。
- 对会移除出口的操作，在保存与执行前核验最新绑定和配置。任何仍有 Provider 绑定的目标出口都应阻止取消，包含停用连接；返回受影响出口及连接，前端解释原因。
- 手动选择、减少并行数量及自动选择遵守同一取消保护。无法获取足够新鲜的绑定信息时，阻止可能移除出口的调整并保留现状；不能把读取失败视为没有绑定。
- 如果执行前发现新绑定或配置变化，停止移除受影响出口并报告未完成，不能把先前验证结果当作永久授权。外部 9Router 管理操作与本工具不构成分布式原子事务，验收不得宣称消除了所有外部竞态。
- 使用可关联本次配置的状态区分保存、出口调整及池同步；旧同步完成不能让新配置显示完成。出口阶段失败应标明失败出口，不显示全部生效。
- 出口生效而池同步失败时，显示“出口已生效，代理池同步失败”及原因，提供重试并保留后台重试；不自动回滚已生效的出口组合。

### 托管代理池与同步

- 由托管台账中的逻辑出口与池身份确定归属，再核验实际地址。历史台账名称不作为当前节点身份依据；名称前缀不能授权接管外部池。
- 新池名称由配置节点显示名和完整逻辑出口身份组成；无法获知配置节点名称时使用稳定出口标识。已有池保留身份，不随备用节点改名。即使出现外部对象占用预期名称，也只能报告明确冲突，不能覆盖外部对象。
- 自动同步与手动同步使用同一规划和执行逻辑。健康出口可建池；暂时不健康的现用出口仍保持对应关系，不能因此被当作废弃对象。
- 已知归属出口的地址修复需确认身份、目标健康和当前配置。归属不唯一、地址被其他对象占用或快照过期时停止修复并报告原因，不凭同名迁移。
- 新池创建后立即持久化归属；后续测试失败仍保留可追踪记录。重试先读取当前远端状态和台账；超时导致结果不确定时核对后再决定是否重试创建，歧义进入待核对状态。
- 旧托管池仅在不再选用、端口不再监听且无绑定时允许清理。有绑定且无明确替代关系的池保留为历史池，并说明保留原因。
- 延续已明确的迁移关系处理能力：目标测试通过后更新绑定，回读确认后才考虑清理。执行前和删除前重新核验出口选择、Broker 实例、归属及绑定，防止旧计划生效。
- 截图中的彰化新旧入口分别处理：当前出口可建立唯一对应池；原 Claude 绑定的历史池保留，不因名称相同迁移。示例端口仅用于验收数据，不硬编码为生产规则。
- 台账记录当前归属与变更审计；重复同步、进程中断和部分失败均能恢复执行，不产生重复池或重复迁移。

### 展示与兼容

- 出口列表展示稳定出口标识、配置节点、实际节点、备用状态、本地入口及对应池；代理池列表反向展示所属出口和绑定连接，历史池有清晰标记。
- Provider 路由展示连接、池、入口与实际节点；缺少任一关系时显示具体断点。
- 同步状态包含待创建、已对应、同步失败、历史保留及冲突待处理。池测试通过不等于当前出口健康，分别显示结果及时间。
- 保持现有视觉风格，兼顾桌面和移动端。公网 IP 哈希仅作观测，不显示已锁定或已保护。
- 兼容既有选择、租约及管理台账，采用增量补充信息；不删除历史恢复数据，不靠重置租约解决冲突。

## Testing Decisions

### 测试边界

- 用户已要求在隔离回归之外增加真实环境写入验收。
- 主验收边界使用真实 Dashboard API：提交配置、读取状态、触发同步并观察最终结果。隔离运行目录与受控 9Router 服务提供外部状态，候选整理、保护校验及同步必须执行真实业务逻辑。
- 复用现有 PowerShell 隔离回归习惯，覆盖 Broker、订阅映射、备用与代理池同步；复用现有 Playwright 浏览器交互模式，验证真实界面的选择、禁用原因、状态和重试。
- 浏览器纯展示场景可使用固定快照，但不能用浏览器拦截伪造成功来替代后端一致性验收。不为每个内部函数单独建立测试边界。
- 好测试从用户操作或模块公开入口进入，断言可见状态、出口保留、绑定关系及池数量等外部结果；不绑定私有调用次数或字段拼装步骤。

### 隔离回归与验收条件

1. 同一来源节点被快照与订阅重复引用时只出现一个可选实体；同名不同身份仍可区分，计数正确。
2. 订阅更新、旧映射缺失和同名歧义不会静默换身份；旧配置仍能读取，未知配置节点明确显示。
3. 实际备用节点显示占用出口，前后端拒绝重复新增；已有出口使用自己的节点不被误判。
4. 有绑定出口的手动取消、数量减少及自动选择均被拒绝，停用连接也包含在受影响列表。
5. 绑定查询失败或执行前绑定变化时不停止受影响出口，页面显示未完成原因。
6. 取消无绑定出口并重选同一节点保留明确的出口身份和租约；选择其他节点不继承绑定。
7. 同名历史池不阻塞不同身份的当前出口创建独立池；历史绑定、外部池和 Provider 启停状态保持原值。
8. 暂时不健康的现用出口不会被当作废弃池清理；历史池在有绑定或端口仍监听时保留。
9. 目标测试失败、绑定写入失败或回读失败时原池不被删除；全部前置条件满足才清理。
10. 重复同步、创建后中断及不确定响应不产生重复池；旧配置或旧 Broker 实例的计划不能继续变更新状态。
11. 出口生效后同步失败保持出口，显示部分成功；重试成功后状态恢复，不把旧完成状态归给新操作。
12. 桌面和移动端可完成选择与重试，错误原因可见，配置节点与实际节点不会混淆，页面无新增脚本错误。

### 真实环境写入验收

- 实施完成并通过隔离回归后，在实际 Broker、Dashboard 和 9Router 上执行真实写入验收；记录版本与启动参数，确保运行进程加载了待验收版本。
- 开始前记录实际出口身份、入口、进程及运行状态，代理池身份和归属，以及所有 Provider 的启停与绑定基线。使用当前读数，不能沿用会话截图作为实时事实。
- 验证当前缺池出口实际创建池、重复同步幂等、同名历史池不会被错误接管，以及同步完成后的双向对应展示。
- 对失败分支及绑定取消保护使用专用临时验收出口、托管池和停用的验收连接；测试凭据不承载真实业务。实际调用 9Router API，并回读绑定与池状态。已有业务 Provider 不充当破坏性测试对象。
- 对绑定保护执行真实配置提交，确认被拒绝后出口仍运行、池及连接绑定仍在；对同步失败和恢复执行真实请求，确认部分成功可见且重试不重复建池。
- 实际现有 Provider 的启停与绑定必须与基线一致；纯代理池同步不应重启已有出口。对部署所必需的进程重启单独记录，不能混入“同步不重启”的断言。
- 清理仅限本轮创建的专用验收对象，先解除验收绑定再删除验收池及出口；回读确认清理结果并保留脱敏证据。为真实选中出口创建的目标池属于交付结果，不作为临时对象清理。
- 若真实环境能力、认证或临时对象创建受限，应报告未通过的具体验收项，不能把隔离测试通过写成真实验收通过。

## Out of Scope

- 公网 IP 基准登记、漂移检测、固定 IP 锁定及异常请求阻断。
- 禁用或重设计现有自动备用策略。
- 手动“更换节点”操作及新的 Provider 绑定管理页面。
- 自动启用 Provider、给未绑定连接分配出口或按同名关系迁移业务绑定。
- 自动接管外部代理池、重置全部租约或清空历史记录。
- 上游线路采购、封号归因及持续可用性保证。
- 整体视觉重设计、远程任务平台发布。

## Further Notes

- 当前工作是在现有实现上修复业务一致性，不是重建代理转发系统。优先复用现有公开接口及回归测试方式。
- 逻辑出口身份稳定不等于公网出口 IP 稳定。本次完成后仍保留自动备用，不能据此宣称 Claude 或其他 Provider 已具备固定 IP 保护。
- 真实环境写入验收已获明确要求；实施者应交付脱敏的前后状态及验收结果，避免记录订阅凭据、令牌或连接密钥。
- 后续按本地任务约定拆成可独立验收的纵向任务，明确阻塞关系；身份、候选、绑定保护及同步状态之间的依赖必须在拆分时体现。
