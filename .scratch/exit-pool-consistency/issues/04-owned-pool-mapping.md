# 04: 建立可靠的出口与代理池对应关系

**What to build:** 健康逻辑出口可以创建并维持唯一、可追溯的托管代理池，同名历史池不再阻塞独立出口；用户能够从出口、池和 Provider 连接双向核对实际关系。

**Blocked by:** 01 明确逻辑出口与节点身份。

**Status:** ready-for-agent

**State:** closed

- [x] 使用托管台账中的逻辑出口与池身份确认归属，再核验本地地址；名称、旧台账显示名或前缀不授权接管、合并或迁移。
- [x] 新池名称包含配置节点显示名和完整逻辑出口身份；配置节点未知时使用稳定出口标识。已有池保留身份，不随备用节点改名。
- [x] 同名不同出口可创建独立池；预期名称被外部对象占用、地址重复或归属歧义时报告明确冲突，不覆盖外部对象。
- [x] 已知归属池的地址修复先确认身份、目标健康及当前配置；快照过期或归属不唯一时停止修复。
- [x] 手动与自动同步共用规划和执行逻辑；暂时不健康的现用出口保持对应关系，不作为废弃池处理。
- [x] 创建后立即记录归属；测试失败仍可追踪。重复同步和中断恢复先核对远端状态与台账，不重复建池；不确定创建结果进入核对流程，不能盲目重试。
- [x] 台账兼容旧记录并保存当前归属和变更审计；端口及现有 Provider 启停与绑定不被静默重置。
- [x] 出口和代理池界面双向展示所属关系；Provider 连接可追踪至池、本地入口和实际节点，缺失关系明确显示断点。
- [x] 展示待创建、已对应及冲突原因；出口健康、池测试结果和绑定完整性分别呈现，并显示检查时间。
- [x] 隔离 API 回归覆盖彰化同名不同端口、外部池、重复地址、创建后测试失败、响应不确定及重复同步；浏览器覆盖关系追踪和错误展示。
- [x] 本任务不新增历史池删除权限；历史池生命周期增强由后续任务完成，已有保留约束继续有效。

**规格覆盖:** 用户故事 4、5、18 至 20、23、26、28、29；隔离验收 7、10 中的建池及归属场景。
