# 02: 修复候选重复与占用判断

**What to build:** 出口配置界面明确区分已有出口与可新增订阅节点，消除重复引用，解释同名节点和不可选原因；用户提交的选择与 Broker 实际采用的目录规则一致。

**Blocked by:** 01 明确逻辑出口与节点身份。

**Status:** ready-for-agent

**State:** closed

- [x] 相同来源身份或已有明确映射的重复引用合并；同名不同身份保留并显示协议及稳定短身份。名称、地区或公网 IP 相同均不能单独触发合并。
- [x] 历史快照保留作恢复记录，未选中的历史槽位不作为额外新节点重复列出；已选但订阅映射缺失的出口保留并标记待核对。
- [x] 无绑定出口取消后重选同一节点，复用已有明确出口身份和端口租约；多个历史映射冲突时要求核对，不分配猜测关系。
- [x] 普通取消 A、选择 B 不自动转移原端口或 Provider 绑定；不新增手动“更换节点”操作。
- [x] 候选总数、筛选结果、已选数量及提交校验基于同一份整理后的目录。
- [x] 灰显条目显示自动选择、数量已满、节点占用或映射待核对等原因；被占用的实际节点显示所属出口。
- [x] 前端与后端共同拒绝新增已被其他出口实际占用的节点；已有出口继续使用自身节点不被误判。保存及采用配置时重新核验变化后的目录和占用。
- [x] 隔离回归覆盖快照与订阅重复、同名不同节点、备用占用、历史歧义、取消后重选及目录变化；浏览器验证选择、筛选、计数和不可选原因。
- [x] 同时覆盖桌面与移动端，不修改自动备用策略或引入公网 IP 去重。

**规格覆盖:** 用户故事 6 至 12、17、27、28；隔离验收 1、3、6。
