# 01: 明确逻辑出口与节点身份

**What to build:** 操作者能够区分逻辑出口、配置节点和实际节点，识别备用状态，并在订阅更新或旧数据缺失时看到可信的身份信息。贯通 Broker 与 Worker 状态、Dashboard 快照和出口界面，沿用现有出口身份和端口租约。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**State:** closed

- [x] 配置节点和实际节点分别持久化或由可靠来源恢复；订阅更新及自动备用不会将实际节点冒充原配置节点。
- [x] 旧快照无法恢复配置节点时，API 和界面明确表达未知及待核对，不根据同名、同地区或相同公网 IP 猜测身份。
- [x] 保持现有逻辑出口身份、选择请求和端口租约兼容；新增状态信息采用兼容扩展，已有配置可继续读取。
- [x] 出口列表显示持续出口标识、配置节点、实际节点、本地入口及备用状态；实际节点变化不改变出口身份。
- [x] 旧数据缺少新字段时页面仍可使用，不显示错误的默认节点或“已保护”状态。
- [x] 通过真实状态发布与快照入口的隔离回归验证正常节点、备用节点、订阅更新和历史信息缺失；浏览器验证桌面与移动端可区分两种节点。
- [x] 保留现有自动备用；不新增固定公网 IP 保护、手动更换节点或 Provider 自动绑定行为。

**规格覆盖:** 用户故事 1、2、3、28；隔离验收 2；架构决策“逻辑出口身份独立于实际节点”。
