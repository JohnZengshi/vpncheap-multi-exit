# 03: 阻止取消仍有绑定的出口

**What to build:** 用户取消出口、减少并行数量或切换自动选择时，仍有 Provider 绑定的出口保持运行。界面解释受影响连接并引导先迁移或解除绑定；保存与执行阶段都实施相同保护。

**Blocked by:** 02 修复候选重复与占用判断。

**Status:** ready-for-agent

**State:** closed

- [x] 保存前核验本次将移除的出口及最新绑定；任何仍有绑定的出口都阻止取消，包含停用的 Provider 连接。
- [x] 返回可供界面展示的受影响出口及连接，保留用户可修正的配置草稿，并说明需先通过已有管理方式迁移或解除绑定。
- [x] 手动取消、减少数量和自动选择均执行保护，不能通过其他配置入口绕过；不新增 Provider 绑定管理页面。
- [x] 获取绑定失败、信息过期或归属不足以确认时，阻止可能移除出口的调整并保留现状，不能把查询失败当成零绑定。
- [x] Broker 实际移除出口前重新核验配置与绑定；新绑定或配置变化导致受影响出口不被停止，并通过状态与界面说明未完成原因。
- [x] 已存在的历史池不因本项保护被倒推删除、迁移或重新绑定；配置操作不改变现有 Provider 启停状态。
- [x] 测试真实配置 API 与 Broker 执行逻辑，覆盖启用及停用连接、三种取消方式、查询失败、过期状态和保存后新增绑定。
- [x] 验收断言被保护出口仍运行、端口与绑定保持，页面有明确错误；不宣称消除了外部 9Router 操作的所有分布式竞态。

**规格覆盖:** 用户故事 13 至 17、29；隔离验收 4、5；架构决策“保护已有绑定，允许出口与代理池分步生效”。
