# 05: 明确历史池保留、迁移与清理

**What to build:** 用户能看懂历史代理池为何保留；只有明确授权的替代关系完成验证后才能迁移绑定，满足全部条件才清理旧池。失败或状态变化时保持可追溯结果。

**Blocked by:** 04 建立可靠的出口与代理池对应关系。

**Status:** ready-for-agent

**State:** closed

- [x] 有绑定且无明确替代关系的历史池保留，状态及界面显示保留原因和关联连接；同名不构成迁移依据。
- [x] 原 Claude 历史池的绑定保持；当前同名出口拥有独立对应池，页面不会将旧池测试通过当作当前出口可用。
- [x] 旧托管池仅在不再选用、端口不再监听且无绑定时允许清理；外部池和暂时不健康的现用池不被删除。
- [x] 延续既有明确迁移入口：目标池测试通过后更新绑定，逐项回读确认，确认无剩余绑定后才考虑删除原池。
- [x] 目标测试失败、绑定写入失败或回读失败时不删除原池；部分迁移如实记录，重试依据最新绑定继续，不伪装成全部成功。
- [x] 迁移前及删除前重新核验出口选择、Broker 实例、池归属和绑定；配置或实例变化时停止旧计划。
- [x] 维护脱敏迁移与清理审计；重复同步或中断后不重复迁移，不因台账仍有历史记录而误删其他对象。
- [x] 隔离回归从同步公开入口验证保留、明确迁移、逐阶段失败、新增绑定、端口仍监听及旧计划失效；浏览器验证历史保留和失败原因。
- [x] 不新增自动启用 Provider、按名称选择迁移目标或公网 IP 保护行为。

**规格覆盖:** 用户故事 21、22、26、29；隔离验收 8、9、10 中的迁移及清理场景。
